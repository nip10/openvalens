## Highlights

- Set private goals for measurable habits, with target, recurring, rolling
  average, and streak rules. Add dated milestones, pause and resume tracking,
  and correct or backdate logged evidence.
- Record actual supplement intake as evidence, including corrections; a
  schedule by itself is not a recorded dose.
- Link a person's water target to a compatible daily water goal without
  silently restoring the prior preference after cutover.
- Attribute sleep evidence to the person it belongs to. Readiness behavior is
  unchanged.

OpenValens is a personal record-keeping and general-wellness app. It is not a
medical device and does not give medical advice.

## Self-hosting: upgrade notes

- Upgrade: `git fetch --tags && git checkout v1.1.0 && deploy/setup.sh upgrade`
  ([Upgrading](https://github.com/nip10/openvalens/blob/v1.1.0/docs/self-hosting/upgrading.md)).
- Migrations: two additive migrations, `20261102090000_goals_foundation` and
  `20261102120000_personal_sleep_ownership`. Back up the exact target database,
  then apply the reviewed migration artifact once and verify its ledger before
  allowing API v2 or owner-aware worker traffic. The ordinary post-deploy
  migration hook must be a no-op after pre-application. No production
  migration has been run as part of preparing this release.
- New or changed settings: none required.
- Breaking changes and manual steps: API v2 is a protocol boundary, separate
  from the semantic release version. Native app 1.1.0 supports API v2 only;
  API v1-only native clients are unsupported and require an update. New
  connection checks block unsupported versions, but already-authenticated old
  binaries may still attempt calls and fail until updated. App 1.1.0 cannot
  connect to an API v1 server. Keep production on API v1 until the native 1.1.0
  store candidates are approved and available, and communicate the required
  app update before server cutover. Test API v2 on an isolated review server
  first.
- Mobile app: server API version 2. App 1.1.0 requires an API v2 server. The
  API v2 production rollout and store availability are not complete or claimed
  by these release notes.
