Fixes for the Android app, and two small fixes on the server.

## Highlights

- **Android: background sync from Health Connect works.** In 1.2.0 it never
  ran: the Android build left out the part that lets the app sync while it is
  closed, so new data arrived only when you opened the app. It now syncs in
  the background again, trackers linked to Health Connect included.
- **Android: the app installs on more devices again.** 1.2.0 asked Google
  Play for Bluetooth and location hardware, so a few devices without them
  could no longer install it. Both are optional again. On a device without
  Bluetooth, Settings › Devices now says "Bluetooth isn't available on this
  device" instead of closing the app.
- **Android: widget taps only from the widget.** Logging water or your next
  supplement from the home-screen widget still saves in one tap. A quick-log
  link opened from another app or a web page now waits for you to tap Save.
- **Connected AI apps show where they connect from,** such as
  "Claude (claude.ai)", in drafts, the timeline, Settings, the consent screen
  and the connection email. An app chooses its own name, so the web address
  next to it shows where it really comes from, and an app that calls itself
  "OpenValens" goes by its address alone. Your personal keys read
  "My script (personal key)".
- **Deleted imported tracker entries stay deleted.** An entry a tracker
  imported from Apple Health or Health Connect no longer comes back on the
  next sync after you delete it.

OpenValens is a personal record-keeping and general-wellness app. It is not a
medical device and does not give medical advice.

## Self-hosting: upgrade notes

- Upgrade: `git fetch --tags && git checkout v1.2.1 && deploy/setup.sh upgrade`
  ([Upgrading](https://github.com/nip10/openvalens/blob/v1.2.1/docs/self-hosting/upgrading.md)).
- Migrations: 1 since the v1.2.0 tag, additive.
  `20261116090000_ai_app_grant_client_host` adds a nullable `client_host` to
  `ai_app_grant` and fills it for existing OAuth grants from their client: the
  client id's host for a metadata-document (CIMD) client, otherwise the host
  of its first redirect URL. The upgrade takes a pre-migrate backup first.
  The other new migration, `20261115142706_custom_tracker_entry_tombstone`
  (the `custom_tracker_entry_tombstone` table for deleted imported tracker
  entries), merged just before the v1.2.0 tag and is already in it, although
  the 1.2.0 notes do not list it. A server on v1.2.0 has it; one upgrading
  from an older version gets both.
- New or changed settings: none.
- Breaking changes and manual steps: none.
- Behaviour change for connected AI apps: every place that names an OAuth app
  (drafts, timeline, Settings, consent screen, connection email) shows its
  host next to its self-declared name. A name that reads as "OpenValens" is
  replaced by the host, on the consent screen and in the grant's label; older
  grants with such a name are shown by their host without changing what is
  stored. Personal key names are unchanged.
- Data rights: deleted imported tracker entries leave a tombstone (the
  tracker, the source and the phone's record id), so the phone's next re-read
  skips them. Tombstones are in the member's export and erasure, and are
  removed with the tracker
  ([Trackers](https://github.com/nip10/openvalens/blob/v1.2.1/docs/trackers.md)).
- Mobile app: server API version 2, unchanged. The store app 1.2.1 connects
  to servers from 1.1.0 on. Update the server to 1.2.1 first: an older server
  does not send the AI app's host, so the app marks AI app names
  "(unverified)".

## Mobile app

- iOS and Android 1.2.1 (build numbers from EAS). Native change: yes, on
  Android only:
  - R8 now optimises release builds (`proguard-android-optimize.txt` in place
    of `proguard-android.txt`, which Google Play reported as low DEX
    optimisation), with keep rules from the new `plugins/android-r8`.
    One of them keeps Expo's headless app loader, which R8 removed in 1.2.0;
    without it background tasks, the health sync among them, could not start.
    Crash traces keep their source file and line numbers.
  - A new `plugins/optional-hardware` declares Bluetooth, Bluetooth LE and
    location hardware as not required, so Play offers the app to the 7
    devices 1.2.0 dropped. `BtClassic` gains a native check for Bluetooth LE
    hardware.
  - A new local module, `modules/home-widget-tap`: the widget's non-exported
    receiver records each tap, and the generated `QuickLog` receiver (same
    class name, so placed widgets stay bound) extends it. The widget links no
    longer carry a nonce.
  - `statusBarTranslucent` is removed from two modals; Android ignores it
    edge to edge.
- iOS has no native change in this release; its build carries the JavaScript
  changes (AI app names).
- Store candidates have not been built or submitted as part of this PR.
